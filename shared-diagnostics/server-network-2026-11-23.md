## 需要调查的内容

1. **时间线和日志**：查看上一次启动的日志（`journalctl --list-boots`、`journalctl -b -1 -k`、`journalctl -b -1`）及当前启动日志，定位 iwlwifi 的报错时间、错误码、次数及紧邻的网络服务异常；检查持久化日志是否存在。
2. **实际联网路径**：识别物理/虚拟网卡、连接方式（Wi-Fi/有线）、`ip -br addr`、`ip route`、`nmcli device status`（如果安装 NetworkManager）、驱动、网卡芯片型号、固件版本、内核版本。确认异常的 iwlwifi 设备是否真的是远程连接使用的主链路。
3. **网络失效范围**：区分物理链路/驱动丢失、DHCP 或路由故障、DNS 故障、局域网可达但公网不通、SSH 或反向隧道单独失效。缺少事发期间的观测证据时，请明确说明无法确认哪一层先失败。
4. **远程服务**：检查本机实际配置的 SSH、Cloudflare Tunnel（如有）及其他远程服务；包括服务当前状态、开机自启、重连行为与事发前后日志。不要假设一定采用某一服务。
5. **Codex**：根据本地 Codex 进程、配置与日志，判断 `app-server-control.sock` 不存在是独立启动问题、网络故障后果，还是现有证据无法关联。
6. **根因与复发风险**：结合硬件、内核、固件及系统日志，对 iwlwifi 的 `-110` 超时 / SYSASSERT 提出按证据强度排序的假设。判断是否有必要更新固件/内核、关闭某项无线省电设置，或者观察即可。避免无依据的“永久修复”。
